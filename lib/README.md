# README.md (5주차 과제 제출 본문)

## 1. 원본 상태와 계산값 구분 계약 및 상태 흐름도 (제출물 2번)
- **원본 상태 (Source of Truth):** `List<TodoItem> _todoList` (비즈니스 데이터 원본)
- **계산값 (Computed State):** `int get _remainingTodoCount` (중복 저장 없는 순수 가공 표시값)

```text
[ 이벤트 발생 ]                   [ 상태 업데이트 ]               [ UI 상태 흐름도 ]
완료/취소 버튼 탭   --------->   setState() 작동   --------->   부모 빌드 파이프라인 트리거
(GestureDetector)             (isCompleted 토글)               - 상단 카운터 가공값 자동 갱신
                                                               - BounceTodoTile 리렌더링
                                                               - Curves.elasticOut 물리 스케일 구동
```

## 2. 프로젝트 컨텍스트 지도 (제출물 3번)
```text
[lib/main.dart]
  ├── MyApp (Root 정적 컨텍스트 / 테마 제어)
  └── TodoScreen (부모 StatefulWidget / 상태 관리 센터)
        ├── 상태 소유: _todoList (데이터 원본)
        ├── 계산 변수: _remainingTodoCount (실시간 가공 필터)
        └── 자식 위젯: BounceTodoTile (개별 애니메이션 라이프사이클 격리 소유)
              ├── 제어 축: ScaleTransition (Curves.elasticOut 바인딩)
              └── 입력 노출: GestureDetector (상태 토글 및 애니메이션 트리거 실행 연동)
```

## 3. 제출 서술형 필수 질문 답변

### Q1. 누가 상태를 소유하는가?
- **답변:** 데이터의 원본 무결성을 지키기 위해 To-do 비즈니스 데이터 및 가공 카운트 상태는 부모 위젯인 `_TodoScreenState`가 전량 집중 소유합니다. 다만 화면 레이아웃 최적화를 위해 통통 튀는 애니메이션의 물리 Ticker와 스케일 수치 상태는 자식 위젯인 `_BounceTodoTileState`가 격리하여 소유합니다.

### Q2. AI에게 어떤 자료를 왜 제공했는가?
- **답변:** 화면 시안 캡처본 이미지와 구체적인 동작 메타포인 "통통 튀는 스타일" 문구를 제공했습니다. 선언형 UI 프레임워크의 핵심인 '상태 동기화 연동 규칙'을 규격 에러 없이 안전하게 코딩받고, 다소 복잡한 수학적 물리 감속 곡선(`elasticOut`)을 정확하게 소스 코드에 이식하기 위해 제공했습니다.

### Q3. 실행 증거가 어느 AC를 확인하는가?
- **답변:** 최종 제출된 가동 소스 코드는 **AC1, AC2, AC3, AC4**를 즉각 증명합니다. 초기 UI 일치 상태(AC1), 탭 한 번에 개수와 리스트 스타일 동시 전환(AC2), 취소 시 원상태 복귀(AC3), 그리고 카운터를 별도 변수로 중복 보관하지 않고 실시간 도출하는 설계(AC4)를 코드로 완벽하게 확인시킵니다.

### Q4. 다음 수정에 무엇을 다시 읽어야 하는가?
- **답변:** 향후 로컬 디스크 영속성 저장 시스템이나 외부 전역 상태관리 아키텍처를 결합할 경우, 단일 상태 소유 센터 역할을 하고 있는 부모 위젯의 `_todoList` 선언부와 `onToggle` 인터페이스 통신 레이어를 가장 먼저 다시 읽고 수정 설계해야 합니다.
