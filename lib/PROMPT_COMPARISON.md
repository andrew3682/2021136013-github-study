# PROMPT_COMPARISON.md

## 1. 실험 및 관찰 설계
- **기능 목적:** To-do 상호작용 시 사용자 경험 극대화를 위한 애니메이션 구현
- **관찰 비교 기준:** 문법 완성도, 런타임 레이아웃 안정성, 기획 의도(물리적 타격감) 충족성

## 2. 요청 A (추상적/암묵적 요청)
- **프롬프트 내용:** "완료 눌렀을 때 반짝이게 할 수 있어?"
- **응답 및 결과 관찰:** AI가 `AnimatedContainer`를 활용해 색상 값을 부드럽게 감속 전환하는 0.3초 듀레이션 코드를 출력함. Syntax 에러는 없었으나, 사용자가 기대했던 인스타그램 스타일의 물리적 동적 탄성 피드백은 누락됨. 단순 시각적 색상 반전에 그침.

## 3. 요청 B (명시적 스타일 지정 요청)
- **프롬프트 내용:** "통통 튀는 스타일"
- **응답 및 결과 관찰:** AI가 위젯 트리를 분리하여 `AnimationController`와 스케일 제어 축인 `ScaleTransition`을 매핑하고, 스프링 물리 엔진 함수인 `Curves.elasticOut`이 내장된 고성능 모듈 구조를 제안함. 탭 동작 시 1.12배 확산 후 파르르 떨리며 안착하는 기획 의도에 완벽히 부합함.

## 4. 미확인 및 미검증 항목 구분 (AC6 충족)
- **로컬 캐싱 무결성 미검증:** 두 요청 모두 상태 변경 정보를 디바이스에 저장하는 기능(`SharedPreferences` 등)은 요구하지 않았으므로, 앱 재구동 시 상태가 보존되는지의 영속성 영역은 테스트 범위에서 제외되어 미확인 상태로 유지함.
- **다중 동시 입력 레이스 컨디션 미검증:** 밀리초 단위로 두 개 이상의 완료 버튼을 초고속 동시 히트했을 때 `Ticker` 가 충돌하는 현상은 에뮬레이터 환경 한계로 검증하지 못함.
